# PostgreSQL Startup Recovery and db_visualizer Notes

This document describes how the RelationalDatabase container handles PostgreSQL startup and how to recover from common issues.

## Lock file and socket handling

On startup, `startup.sh` now:
- Checks if PostgreSQL is already ready on the configured port (default 5001) and exits early if so.
- Detects and stops any conflicting PostgreSQL process bound to that port using `pg_ctl -m fast stop`.
- Detects stale lock file `postmaster.pid` in the data directory and:
  - Reads the PID inside.
  - If the PID is not alive, removes `postmaster.pid` and leftover socket files `.s.PGSQL.<port>` safely.
  - If the PID is alive, aborts to prevent corruption and prints instructions.

Data directory: `/var/lib/postgresql/data` (or `$PGDATA` if set)

## Manual recovery steps (if needed)

If startup fails with:
- `FATAL: lock file "postmaster.pid" already exists`
- or waiting for socket `.s.PGSQL.5001` never succeeds

Do the following:

1) Check if the PID in the lock is running:
   ```
   LOCK="/var/lib/postgresql/data/postmaster.pid"
   if [ -f "$LOCK" ]; then
     head -n1 "$LOCK"
   fi
   ```

2) If a process exists and is PostgreSQL, stop it gracefully:
   ```
   sudo -u postgres /usr/lib/postgresql/$(ls /usr/lib/postgresql/ | head -1)/bin/pg_ctl \
     -D /var/lib/postgresql/data -p 5001 -m fast stop
   ```

3) If the PID is not running (stale lock), remove lock and sockets:
   ```
   sudo rm -f /var/lib/postgresql/data/postmaster.pid
   sudo rm -f /var/lib/postgresql/data/.s.PGSQL.5001 /var/lib/postgresql/data/.s.PGSQL.5001.lock
   ```

4) Re-run the startup script:
   ```
   bash RelationalDatabase/startup.sh
   ```

If port 5001 is in use by another service, free it or set `DB_PORT` before running the script:
```
DB_PORT=5433 bash RelationalDatabase/startup.sh
```

## db_visualizer Node.js dependencies

The script ensures Node dependencies are installed for the lightweight DB viewer:
- On startup, if `npm` is available and `node_modules` is absent or `express` is missing, it runs `npm ci` (fallback to `npm install`) in `RelationalDatabase/db_visualizer`.

Manual steps if you need to run the viewer directly:
```
cd RelationalDatabase/db_visualizer
npm install
source postgres.env
npm start
```

Ensure environment variables are present (generated by startup.sh):
- POSTGRES_URL
- POSTGRES_USER
- POSTGRES_PASSWORD
- POSTGRES_DB
- POSTGRES_PORT

## Connection quick reference

- psql:
  ```
  psql -h localhost -U appuser -d myapp -p 5001
  ```
- Connection string saved in `RelationalDatabase/db_connection.txt`

## Notes

- Never delete `postmaster.pid` if the process ID is alive; stop PostgreSQL first.
- The script uses `pg_isready` and `pg_ctl` for safe lifecycle management.
- If `npm` is not available in the environment, install Node.js or run the viewer in an environment that has Node.
